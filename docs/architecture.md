# Architecture Map

This document provides a high-level map of the `actuary_engine` codebase to assist developers and quants in navigating the valuation system.

## Module Hierarchy

```text
actuary_engine/
├── tables/          # Parsers and state managers for tabular data (MortalityTable, LapseTable)
├── curves/          # Economic curves, discounting engines, and survival probability calculators
├── pricing/         # Deterministic product models (WholeLife, Term, Annuity)
├── stochastic/      # Simulation engines (Monte Carlo runner, Vasicek, dynamic lapse)
├── models/          # Base classes and structural interfaces for actuarial liabilities
├── projections/     # Cash flow generation and temporal state mapping
└── utils/           # Helper functions (interpolation routines, mathematical utilities)
```

## Dependency Graph

The codebase enforces a strictly unidirectional dependency flow:

1. **`utils/` and `tables/`** form the foundational data layer. They have no internal dependencies on higher-level modules.
2. **`curves/`** relies on `tables/` to convert mortality rates into cumulative survival probabilities.
3. **`projections/`** uses `tables/` and `curves/` to map out un-discounted temporal cash flows.
4. **`pricing/`** (Deterministic) depends heavily on `projections/` and `curves/` to calculate single-point EPVs.
5. **`stochastic/`** is the top-level orchestrator. It wraps modules from `pricing/` and `curves/`, injecting randomized arrays generated by SDE engines to compute vector-based liabilities.

## Public Entry Points

To run a valuation, a user typically interacts with:
* `actuary_engine.tables.mortality_table.MortalityTable`: To load demographic data.
* `actuary_engine.pricing.insurance.WholeLife`: To run deterministic point estimates.
* `actuary_engine.pricing.stochastic_insurance.StochasticWholeLife`: To run full Monte Carlo BEL distributions.
